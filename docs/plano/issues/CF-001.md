## Contexto

O repositório ainda é o template counter. Sem uma base de dependências, tema, rotas e CI, cada feature nasceria com decisões divergentes e sem verificação automática.

## História

**Como** time de desenvolvimento
**quero** o projeto Flutter configurado com dependências, tema, rotas e pipeline
**para** entregar histórias com padrão único e sem regressões.

## Regras de negócio

- **RN01** — Flutter stable; SDK `^3.13.0`; dependências: `supabase_flutter`, `flutter_riverpod`, `riverpod_annotation`, `go_router`, `freezed_annotation`, `json_annotation`, `intl`.
- **RN02** — Dev: `build_runner`, `riverpod_generator`, `mocktail`, `riverpod_lint`, `custom_lint`.
- **RN03** — `main.dart` inicializa `ProviderScope` + `Supabase.initialize` com URL/anon key via `--dart-define` (nenhum segredo versionado).
- **RN04** — Rotas base: `/login`, `/pai`, `/pdv`, `/gestor`; guard redireciona não autenticado para `/login` e por role.
- **RN05** — Tema atual (Lato/Dosis em `lib/src/core/theme`) preservado no `MaterialApp.router`.
- **RN06** — CI roda `flutter analyze` e `flutter test` em todo PR.

## Critérios de aceite

- [ ] **CA01** — `flutter run` sobe o app em Android sem erro.
- [ ] **CA02** — `flutter analyze` retorna "No issues found".
- [ ] **CA03** — `flutter test` passa (incluindo o teste de widget atualizado).
- [ ] **CA04** — Sem sessão, qualquer rota redireciona para `/login`.
- [ ] **CA05** — Após login, o role direciona para o shell correto (`/pai`, `/pdv` ou `/gestor`).
- [ ] **CA06** — Workflow de CI executa analyze + test em PR e fica verde.
- [ ] **CA07** — Nenhuma credencial em arquivo versionado.
