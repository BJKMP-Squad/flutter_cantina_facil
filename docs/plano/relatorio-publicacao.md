## 7. Divergências e observações

1. **Limite de API do GraphQL:** `gh project item-edit` custa ~37 pontos por chamada e disparou limite secundário de burst após 8 itens. A execução foi refeita com mutações GraphQL em lote (1 requisição por item, 7 campos). Nenhum dado ficou inconsistente — a verificação final confirmou 140/140 valores.
2. **Log de publicação:** o primeiro check de idempotência comparava apenas o `id`, que também aparece nas linhas de issue. Os 12 registros de campos faltantes foram reconstruídos a partir do estado real verificado e o log foi normalizado com o campo `alvo` (`issue`/`item`).
3. **Vencimento das milestones:** o GitHub normaliza `due_on` para data (00:00:00Z); as sprints vencem nos dias 16, 23 e 30/11.
4. **Agrupamento/ordenação das views:** a API só expõe `visibleFieldIds`; agrupar "Por épico" por Épico e ordenar por Prioridade precisa ser feito uma vez na UI.
5. **Épicos:** não são issues. A rastreabilidade é feita pelo campo `Épico` (8 opções) — decisão confirmada no dry-run.
